# Rahul Mourya, portfolio

Personal site built with Next.js (App Router), Tailwind CSS, and file based content.

## Stack

- **Next.js 16** App Router, static generation, metadata API, `next/og` for social images
- **TypeScript**
- **Tailwind CSS** with design tokens as CSS variables, plus `@tailwindcss/typography` for post bodies
- **Markdown content** via `gray-matter` and `marked`, rendered at build time
- **No animation library.** Motion is CSS: keyframes for entrances and scroll driven `animation-timeline: view()` for reveals

## Routes

| Route | What it is |
|---|---|
| `/` | Intro, featured projects, latest posts |
| `/work` | Toolkit and work history |
| `/projects` | All projects, filterable by tag |
| `/blog` | Post list with search, topic and tag filters, plus posts published on Medium |
| `/blog/[slug]` | A post |
| `/contact` | Email and profiles |
| `/robots.txt`, `/sitemap.xml` | Generated from `app/robots.ts` and `app/sitemap.ts` |

## Content

Everything is a markdown file, so a post or project is a pull request.

```
content/
  blog/<slug>.md          one post, frontmatter + body
  projects/<order>-<slug>.md  one project, frontmatter only
  external/medium-feed.xml    snapshot of the Medium feed, used as a build fallback
```

Blog frontmatter:

```yaml
---
title: "Post title"
slug: "post-title"        # must match the file name
description: "Doubles as the meta description, keep it under 160 characters"
date: "2026-07-14"
updated: "2026-08-01"     # optional
topic: "CSS"              # groups posts, shown as a badge
tags: [viewport, mobile]
draft: false              # drafts are excluded from the site and the sitemap
---
```

Decap CMS is wired up for both collections at `/admin`. For local editing run
`npm run cms` in one terminal and `npm run dev` in another, then open
[http://localhost:3000/admin](http://localhost:3000/admin).

### Posts published elsewhere

`/blog` also lists writing from Medium. The feed is fetched at build time and
revalidated daily. `content/external/medium-feed.xml` is a committed snapshot
used if the feed is unreachable, so a Medium outage cannot fail a deploy.
Refresh it with:

```bash
npm run sync:medium
```

## SEO

- Unique title and description per route, written by hand, not templated
- Canonical URL on every page
- Open Graph and Twitter cards, with images generated by `next/og`
  (`app/opengraph-image.tsx` for the site, `app/blog/[slug]/opengraph-image.tsx` per post)
- JSON-LD: `Person` and `WebSite` at the root, `BlogPosting` per post,
  `SoftwareApplication` or `CreativeWork` per project, `BreadcrumbList` on nested routes
- `robots.txt` and a `sitemap.xml` that includes every published post

The absolute base URL comes from `NEXT_PUBLIC_SITE_URL`, falling back to
`VERCEL_PROJECT_PRODUCTION_URL` and then to the production domain. Set it in
`.env.local` when running against a different host:

```bash
NEXT_PUBLIC_SITE_URL=http://localhost:3000
```

## Getting started

Requires Node 20 or newer.

```bash
npm install
npm run dev
```

## Scripts

```bash
npm run dev          # dev server on 127.0.0.1:3000
npm run build        # production build
npm run start        # serve the production build
npm run lint         # eslint, flat config
npm run cms          # Decap CMS local backend, for editing at /admin
npm run sync:medium  # refresh the committed Medium feed snapshot
```

## Deploy

Vercel. Push to `main` deploys to production.
